Configurer Google Drive

Retrouver à M2I une copie de l’inventaire mis à jour à la maison.

Ce qui va se passer

Tu autorises CKIN2 à déposer des archives dans un dossier Drive que tu choisis. Après une mise à jour enregistrée, CKIN2 envoie une nouvelle archive. À M2I, tu télécharges la plus récente pour la consulter.

La connexion Steam sert à identifier un compte Steam. La connexion Google autorise les sauvegardes Drive. Ce tutoriel configure Google ; la connexion Steam sera ajoutée séparément. Le site public du projet n’est pas nécessaire pour cette configuration locale.

Cette page est un guide : elle ne connecte aucun compte et ne publie aucun fichier en s’ouvrant.

1. Préparer ton dossier

  1. Ouvre Google Drive avec le compte qui possède ton inventaire.
  2. Crée un dossier privé pour CKIN2, ou réutilise celui que tu as déjà choisi.
  3. Garde son lien pour la connexion. Ne le colle pas dans un fichier du projet destiné à GitHub.

Aucune installation de Google Drive pour ordinateur n’est nécessaire avec cette méthode.

2. Identifier CKIN2 auprès de Google

Google appelle cette fiche un « projet Google Cloud ». Elle permet d’afficher une demande de connexion au nom de CKIN2. Elle ne donne pas, à elle seule, accès à ton Drive.

  1. Ouvre la console Google Cloud et sélectionne le bon compte.
  2. Lors de la première visite, lis et accepte les conditions si elles te conviennent.
  3. Clique sur Créer un projet, nomme-le CKIN2, puis sélectionne-le.
  4. Dans API et services → Bibliothèque, recherche et active Google Drive API, puis Google Picker API. Le second affiche le choix du dossier.

Ce parcours ne demande pas d’activer un essai gratuit ni de créer un compte de facturation.

3. Préparer l’écran de connexion

  1. Ouvre Écran de consentement OAuth ou Google Auth Platform, puis commence la configuration.
  2. Indique CKIN2 comme nom de l’application, une adresse d’assistance disponible et une adresse de contact que tu contrôles.
  3. Pour un compte Google personnel, choisis l’audience Externe. Garde l’application en test au départ et ajoute ton compte Google dans les utilisateurs de test.
  4. Lis les règles et déclarations affichées par Google avant de les valider.
  5. Dans Clients, crée un ID client OAuth de type Application de bureau. Donne-lui par exemple le nom CKIN2 sur mon PC.
  6. Télécharge son fichier JSON et place-le dans le dossier privé .secrets du projet, sous le nom client_secret.json.

Le fichier JSON contient la configuration de connexion. Il reste sur ton PC, hors de Git et des archives d’inventaire. En mode test Google peut demander une nouvelle connexion après expiration de l’autorisation.

4. Connecter Google une première fois

Depuis le dossier CKIN2, ouvre le terminal de ton environnement Python et lance :

python -m pip install -r requirements-cloud.txt
python src/google_drive_cloud.py connect --client-secrets ".secrets/client_secret.json"
  1. Si CKIN2 te le demande, colle le lien de ton dossier dans la saisie masquée. S’il a déjà été enregistré dans ta configuration privée, cette étape est automatique.
  2. Dans le navigateur, choisis le compte Google qui peut écrire dans ce dossier.
  3. Si le navigateur ne s’ouvre pas, ouvre toi-même le fichier temporaire privé data/runtime/google-connect.html. Il mène à la même demande officielle et sera supprimé à la fin.
  4. Si Google affiche « Google n’a pas validé cette application », il s’agit de la version de test. Lis l’avertissement. Si tu fais confiance à ton application CKIN2, le bouton Continuer poursuit la demande ; Revenir en lieu sûr l’annule. Une page d’aide Google ne confirme pas la connexion.
  5. Vérifie ensuite la demande d’autorisation, puis sélectionne le même dossier Drive. Termine la validation Google.
  6. Reviens dans CKIN2 : le message de connexion réussie confirme l’activation des publications automatiques.

Le mot de passe reste chez Google. L’autorisation et la destination sont conservées localement, protégées par ton compte Windows. Les archives n’emportent pas ces autorisations.

5. Vérifier une première sauvegarde

Dans le dashboard, clique sur Copier l’inventaire dans le cloud. Le message indique la progression et le résultat. Ce bouton sauvegarde les données déjà enregistrées ; il ne lance pas une collecte de prix. Tu peux aussi utiliser :

python src/google_drive_cloud.py publish

Attends le message confirmant l’envoi Google Drive, puis ouvre ton dossier Drive : une archive datée ckin2-….zip doit apparaître.

Ensuite, les mises à jour « home », le bouton d’actualisation Steam du dashboard, les imports Steam validés et la conversion des catégories déclenchent la publication. Une modification de CSV faite à la main doit être suivie d’une mise à jour « home ». En cas d’échec réseau, les données locales sont conservées ; relance la publication ou attends la prochaine mise à jour. Le mode « school » ne publie rien.

6. Retrouver ton inventaire à M2I

  1. Télécharge la dernière archive terminée depuis ton dossier Drive.
  2. Dans la copie du projet installée à M2I, restaure-la vers un nouveau dossier. Adapte les chemins ci-dessous.
python src/cloud_inventory.py restore "C:\chemin\archive.zip" --destination "D:\CKIN2-cloud\copie-01"
python src/dashboard.py --root "D:\CKIN2-cloud\copie-01"

Ouvre le tableau de bord local et vérifie les dates des prix et de l’inventaire. Pour une nouvelle archive, utilise un nouveau dossier, par exemple copie-02. La restauration refuse d’écraser un dossier existant.

En cas de difficulté

Snapshot, archive cloud et prévision : quelle différence ?

Un snapshot est un état daté des objets et quantités de ton inventaire. Ouvrir le dashboard ne le crée pas : une mise à jour « home » enregistre celui du mois, et une nouvelle mise à jour dans le même mois le remplace.

Une archive cloud est une copie transportable des données. En publier plusieurs le même jour n’ajoute pas des mois d’historique. Le modèle de prévision apprend sur les prix mensuels : il demande au moins 12 exemples d’apprentissage valides, donc plus de 12 mois de prix dans le cas habituel. Le mois en cours et les périodes inexploitables ne suffisent pas à compléter cet historique.

Google refuse le compte ou le dossier

Vérifie que tu utilises le compte ajouté comme utilisateur de test, qu’il possède un droit d’écriture sur le dossier, et que tu as sélectionné le même dossier pendant la connexion. Recommence la commande de connexion si nécessaire.

Une autorisation a expiré

Relance la commande de connexion. Les configurations Google en test peuvent exiger une reconnexion périodique. Ne contourne pas un avertissement de sécurité du navigateur.

Arrêter les sauvegardes automatiques
python src/google_drive_cloud.py disconnect

Cette commande supprime l’autorisation enregistrée sur ce PC. Pour retirer aussi l’accès chez Google, supprime CKIN2 dans les connexions aux applications tierces de ton compte Google. Les archives déjà envoyées restent dans ton dossier privé.

Les noms de menus Google peuvent évoluer. Pour les références techniques : connexion des applications de bureau et choix du dossier Google.
